# 0.2.1 — 2026-10-08

## Added

- **GFM oracle in the tests**: rendered Markdown is parsed with micromark and its GFM extensions, and seeded property tests run the inline paths against it ([#68](https://github.com/cyanheads/scholarly-parse/issues/68)). The corpus `expect.json` gains `referenceIdentifiers`.

## Changed

- **Documentation**: `baseUrl` for arXiv HTML is `https://arxiv.org/html/<id>` without a trailing slash, the only form its image paths resolve against.

## Fixed

- **`toText`** no longer leaves a `**` when emphasis inside strong text opens after punctuation or a letter ([#56](https://github.com/cyanheads/scholarly-parse/issues/56)).
- **Emphasis** that GFM printed literally beside a word now renders: edge punctuation moves outside the marker (`*daf-16-*dependent` → `*daf-16*-dependent`) and touching spans of one kind join ([#72](https://github.com/cyanheads/scholarly-parse/issues/72)).
- **`__word__`** text no longer renders as emphasis ([#63](https://github.com/cyanheads/scholarly-parse/issues/63)).
- **Touching inline formulas** keep a TeX control word apart from the letter after it (`$\alpha$$x$` → `$\alpha x$`) ([#52](https://github.com/cyanheads/scholarly-parse/issues/52)).
- **A link whose text is its URL** is written as an autolink when the URL holds `~` or an underscore beside punctuation, with parentheses unencoded ([#53](https://github.com/cyanheads/scholarly-parse/issues/53)).
- **JATS citations**: touching citation `<xref>`s read `[1,2,3]` ([#57](https://github.com/cyanheads/scholarly-parse/issues/57)); `<mixed-citation>` names keep their separators and an empty `<etal/>` reads `et al.` ([#58](https://github.com/cyanheads/scholarly-parse/issues/58)); a `<name-alternatives>` no longer fuses both name forms ([#73](https://github.com/cyanheads/scholarly-parse/issues/73)).
- **`jatsInlineToMarkdown`** keeps tag-shaped text (`x<y and y>z`) and separates HTML block boundaries ([#61](https://github.com/cyanheads/scholarly-parse/issues/61)).
- **JATS**: TeX in an IOP `<?CDATA …?>` instruction reads as the formula ([#60](https://github.com/cyanheads/scholarly-parse/issues/60)), and `<app-group>` children other than `<app>` and a supplement's own paragraphs are kept ([#69](https://github.com/cyanheads/scholarly-parse/issues/69)).
- **XML well-formedness**: an apostrophe in a DOCTYPE comment no longer makes a well-formed document `malformed` ([#74](https://github.com/cyanheads/scholarly-parse/issues/74)), and a start tag whose name runs into other characters or a `<!…>` declaration outside a DOCTYPE, which the XML parser silently dropped, is `malformed`.
- **PMC IDs, PMIDs, and ORCID iDs** go through `normalizePmcid`, `normalizePmid`, and `normalizeOrcid` for every JATS, TEI, and HTML field: labels and PMC, PubMed, or orcid.org links are removed, any case reads, and a value that is not an identifier is left out ([#59](https://github.com/cyanheads/scholarly-parse/issues/59)).
- **arXiv IDs** read through one grammar in every format: LaTeXML and PDF references read old-style IDs and arxiv.org links, HTML references keep a printed version, and an old-style subject class is dropped ([#65](https://github.com/cyanheads/scholarly-parse/issues/65)).

## Security

- **Outside link text, rendered Markdown never yields a live HTML node**: a bare URL GFM links that holds or meets an escape is written as an explicit link to the URL as the source has it, and inline TeX cannot close its own `$…$` or open a code span ([#62](https://github.com/cyanheads/scholarly-parse/issues/62), [#68](https://github.com/cyanheads/scholarly-parse/issues/68)).
