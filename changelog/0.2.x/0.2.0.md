# 0.2.0 — 2026-10-06

## Added

- **`PdfOptions.signal` and `AutoParseOptions.signal`**: an aborted `AbortSignal` stops a PDF read at the next page boundary, keeping what was read with a `truncated-input` warning ([#17](https://github.com/cyanheads/scholarly-parse/issues/17)). With a signal, each page waits one `setTimeout` turn so a timeout can fire.
- **`toSections` ends with `footnotes` and `references` entries** after `floats`, each holding what `toMarkdown` writes for it, and `toMarkdown({ sections })` renders them ([#27](https://github.com/cyanheads/scholarly-parse/issues/27)). `FlatSection.kind` gains both.
- **PDF footnotes**: labelled notes set below a page's text before the reference list become `document.footnotes`; first-page affiliations and licences stay front matter ([#43](https://github.com/cyanheads/scholarly-parse/issues/43)).
- **`detect`** reads bytes by their UTF-8 or UTF-16 byte-order mark, skips processing instructions before the root, names an `<article class="ltx_document">` fragment LaTeXML, and names JATS inside a PMC OAI-PMH record, which `parseJats` reads with flavor `pmc` ([#31](https://github.com/cyanheads/scholarly-parse/issues/31), [#45](https://github.com/cyanheads/scholarly-parse/issues/45)).

## Changed

- **Section IDs**: `issueId` never gives a section a `toSections` ID (`abstract-<n>`, `floats`, `footnotes`, `references`), and every reader numbers abstract parts `abstract-<n>-<m>`, so each `toSections` ID renders one entry ([#24](https://github.com/cyanheads/scholarly-parse/issues/24)).
- **Publisher HTML lead**: on a titled page with no abstract, article prose between the title and the first heading opens the body, byline still dropped ([#32](https://github.com/cyanheads/scholarly-parse/issues/32)).
- **Publisher HTML landing pages** parse as front matter and an abstract with a `no-body` warning that names a landing page; the title heading falls back to the one matching `citation_title`, and `Metadata`/`BibTeX` sections are furniture ([#30](https://github.com/cyanheads/scholarly-parse/issues/30)).
- **JATS footnotes** write every block of a note into its text (lists, formulas, code, captions; a table's rows are warned `unhandled-element`), definitions keep their paragraphs, and block elements read as inline text are spaced ([#35](https://github.com/cyanheads/scholarly-parse/issues/35)).

## Fixed

- **DOIs** in JATS and TEI article, related-work, and reference fields lose resolver and `doi:` prefixes, through one shared `normalizeDoi` ([#38](https://github.com/cyanheads/scholarly-parse/issues/38)).
- **`toText`** strips links whose label holds brackets, and `link()` escapes a label's unpaired brackets, leaving inline math alone ([#36](https://github.com/cyanheads/scholarly-parse/issues/36)).
- **MathML** `mmultiscripts` keep prescripts and postscripts (`{}_6^{14}C`) ([#40](https://github.com/cyanheads/scholarly-parse/issues/40)), and LaTeXML and publisher HTML convert MathML that carries no TeX instead of dropping or flattening it ([#41](https://github.com/cyanheads/scholarly-parse/issues/41)).
- **Publisher HTML metadata**: `<a rel="license">` and `<area rel="license">` are read as the license ([#29](https://github.com/cyanheads/scholarly-parse/issues/29)), and an `<h1>` fallback title is escaped once ([#33](https://github.com/cyanheads/scholarly-parse/issues/33)).
- **PDF**: runs drawn under a heading no longer join its line ([#2](https://github.com/cyanheads/scholarly-parse/issues/2)); a figure's panel labels are not headings ([#3](https://github.com/cyanheads/scholarly-parse/issues/3)); bold back-matter labels after the last reference end the list ([#5](https://github.com/cyanheads/scholarly-parse/issues/5)); one- and two-entry numbered bibliographies and `68.[No title]` entries split ([#42](https://github.com/cyanheads/scholarly-parse/issues/42)); a quoted or colon-less first-page DOI is read ([#23](https://github.com/cyanheads/scholarly-parse/issues/23)).

## Security

- **Inline escaping holds across element boundaries**: `escapeInline` closes each fragment's end and every reader runs `joinInlineSeams` over finished inline Markdown, so text split across elements cannot form raw HTML, an image, or a non-web link; citation markers are escaped ([#44](https://github.com/cyanheads/scholarly-parse/issues/44)).
- **HTML and LaTeXML nesting is bounded before the DOM is built**: tags of elements past 256 levels are dropped with their text kept and a `truncated-input` warning, and walkers read each element's subtree facts once, so deep or chained markup parses in linear time ([#7](https://github.com/cyanheads/scholarly-parse/issues/7)). Repeated self-closed `<math/>` and `<svg/>` are bounded the same way.
- **Linear-time lookups**: HTML and LaTeXML affiliations, HTML in-page link targets, JATS trailing `<notes>` ([#10](https://github.com/cyanheads/scholarly-parse/issues/10)), and a LaTeXML paragraph holding many footnotes.
