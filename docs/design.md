# scholarly-parse — design

Parse the formats scholarly papers are published in into one document model, and render that model as Markdown an LLM or a person can read. The model is the contract; every format parser feeds it and every renderer reads it.

## Scope

| In | Out |
|:---|:---|
| Parsing bytes or text the caller already has | Fetching, resolving DOIs, following links, rate limiting |
| JATS XML, Grobid TEI (both shapes), arXiv LaTeXML HTML, publisher article HTML, PDF | Legal and regulatory formats — a future sibling package, `legal-parse`, built around Akoma Ntoso |
| Detecting the format of a payload, and challenge pages served in its place | Getting past a challenge page |
| Markdown, plain text, and a flat section list with sizes | Paging a long document for an MCP tool — `@cyanheads/mcp-ts-core` ([#558](https://github.com/cyanheads/mcp-ts-core/issues/558)) consumes the section list |
| Bun, Node ≥22, Cloudflare Workers | CommonJS, browsers without a bundler |

## Public API

```ts
// Package root: the model, detection, any-format parsing, renderers.
import { detect, parse, toMarkdown, toText, toSections, type ScholarlyDocument } from 'scholarly-parse';

// One subpath per format, so an application loads only what it parses.
import { parseJats, jatsInlineToMarkdown } from 'scholarly-parse/jats';
import { parseTei } from 'scholarly-parse/tei';
import { parseLatexml } from 'scholarly-parse/latexml';
import { parseHtml } from 'scholarly-parse/html';
import { parsePdf } from 'scholarly-parse/pdf';
```

- Every parser returns a `ParseResult`: `{ ok: true, document }` or `{ ok: false, error: { reason, message } }`. Expected failures are values — `malformed`, `wrong-format`, `empty`, `blocked`, `too-large`. A missing optional peer dependency is a setup error and throws with the install command.
- XML parsers are synchronous. HTML and PDF parsers are async because their engines load on first use.
- `detect(input)` names the format from the payload's opening 64 Ki characters, reading bytes by their byte-order mark (UTF-8 or UTF-16), else as Latin-1: a PDF header, a TEI root, LaTeXML's markers (an `<article class="ltx_document">` root included), a JATS root (bare, in `<pmc-articleset>`, or in an OAI-PMH record's `<metadata>`) past the XML declaration, processing instructions, and comments, or HTML markup. A captcha or bot check served where a paper was promised is HTML, and the HTML parser reports it as `blocked`.
- `parse(input, { format?, baseUrl?, maxInputBytes?, maxPages?, maxTextItems?, maxTextChars?, maxOperators?, signal? })` detects the format (or takes the caller's) and runs that parser, loading it on first use (`signal` and the reading budgets apply to PDF).
- `jatsInlineToMarkdown(fragment)` converts a JATS fragment (a Crossref or Europe PMC abstract) without a full article around it.

## The model

`src/model/document.ts` is the single source of truth; this is its outline.

| Part | Holds |
|:---|:---|
| `metadata` | Title, subtitle, authors (ORCID, affiliations, corresponding), identifiers (DOI, PMID, PMCID, arXiv), venue, date as precise as the source states it, keywords, article type, language, license passed through verbatim, related works (what a correction corrects, the notice retracting the article) |
| `abstracts[]` | Every abstract with its `kind` (`main`, `graphical`, `plain-language`, `teaser`, `other`); structured abstracts keep their titled sections |
| `body[]`, `back[]` | Section trees. A section has an ID stable within the document, a `kind`, an optional label and title, typed blocks, and subsections |
| Blocks | `paragraph`, `list`, `table` (rectangular rows, spans expanded, or an `unextractable` reason), `figure`, `formula` (TeX when the source has it, else linear text), `code`, `quote`, `box`, `supplement` |
| `floats[]` | Figures and tables the source places outside any section |
| `references[]`, `footnotes[]` | Every reference keeps its full citation as text, plus structured fields when the source marks them up |
| `diagnostics` | `quality` (`structured` / `partial` / `flat`), coded warnings, and unhandled source elements with counts |

Inline text is CommonMark with GFM: emphasis, links, `$…$` math where the source carries TeX, citation markers as printed. Block structure is typed, so a renderer never re-parses Markdown to find a table.

## Formats

| Subpath | Reads | Starting point | Quality |
|:---|:---|:---|:---|
| `/jats` | JATS 1.x in the Archiving and Publishing tag sets, as served by PMC, Europe PMC, bioRxiv, and publisher TDM feeds | The parser hardened in `pubmed-mcp-server` (`src/services/ncbi/parsing/`), moved here unchanged and then reshaped to the model | `structured` |
| `/tei` | Grobid TEI: the standard `<TEI>` document (`text/body/div`) and the lowercase `<tei>` wrapped in HTML (`text/div`, with `<back>` beside `<text>`) that OpenAlex serves | New | `structured` |
| `/latexml` | arXiv's `arxiv.org/html` and ar5iv renders | The boilerplate stripping in `arxiv-mcp-server`, replaced by a real conversion | `structured` |
| `/html` | Article pages from publishers and preprint servers | A walker over a `linkedom` DOM: `citation_*` and Dublin Core metadata, the article container, headings as the section tree, and page furniture skipped | `partial` |
| `/pdf` | PDF with a text layer | `unpdf` text runs with their fonts, laid out into columns and reading order, then structure from typography: title and abstract from the first page, headings by size, weight, numbering, and name, captions by label, footnotes by label below a page's text, references by numbering or indentation | `partial` or `flat` |

Elsevier full-text XML (its own `xocs`/`ce:` schema, not JATS) is a later format ([#28](https://github.com/cyanheads/scholarly-parse/issues/28)).

**Dependencies.** `fast-xml-parser` is the one required dependency. `linkedom` and `unpdf` are optional peers, loaded on first use.

## Quality engine

The parsers are only as good as the documents they have been run against. Quality comes from five layers, all under `tests/corpus/` and `corpus/`.

1. **Corpus.** Real documents stored byte-for-byte in `corpus/<format>/<fixture-id>/`, each with a `meta.json` recording where it came from, its license, and what it exercises. Only openly licensed documents (CC BY, CC0, and similar) — `corpus/README.md` holds the rules, and `corpus/ATTRIBUTION.md` credits every one.
2. **Per-fixture assertions** in `expect.json`: section titles in order, table shapes, formula TeX, the main abstract's opening, reference counts, and any regression the fixture exists for. Plus `expected.md`, a reviewed Markdown snapshot.
3. **Invariants** checked on every document: no leaked source tags or entities, no TeX preambles, every table, figure, and reference in the source accounted for, no empty headings, no split surrogate pairs, deterministic output.
4. **Cross-format agreement.** A rosetta set of works stored in several formats (JATS, PDF, publisher HTML, Grobid TEI generated from the PDF, and LaTeXML when an arXiv version exists). The JATS parse is the reference: `bun run corpus:agreement` measures the other formats against it on section titles, abstract, reference count, and table and figure counts, which gauges PDF and HTML quality without hand labeling.
5. **Wild sampling.** `bun run corpus:sample` pulls fresh openly licensed documents from Europe PMC, arXiv, and OpenAlex (its sampled CC BY articles as publisher PDFs and pages, and Grobid TEI with a key), runs the invariants, and groups failures by element and publisher. Each new failure class becomes a fixture.

Every parsing bug fixed in a consumer before this package existed becomes a named regression fixture, with the issue recorded in `meta.json`.

## Decisions

- **Reuse pubmed's JATS parser rather than wrap MyST's.** On ten Europe PMC articles, the pubmed parser kept all 24 tables and every display formula; `jats-to-myst` → `myst-to-md` rendered no tables, dropped display math, wrote MyST dialect, and pulled 199 packages.
- **Parse only; never fetch.** Fetching carries policy (rate limits, licenses, challenge handling) that belongs to the consumer, and a pure parser runs anywhere.
- **Results, not exceptions, for bad input.** Malformed and blocked documents are normal in the wild; a caller branches on `ok` instead of wrapping every call in `try`. Each parser's entry also catches what it did not anticipate (a stack overflow on deep nesting, an engine's internal error) and returns `malformed`, so a document that finds a bug still keeps the contract.
- **Inline Markdown, typed blocks.** Consumers render Markdown almost always; typing the blocks keeps tables, formulas, and figures addressable without a second parser.
- **Escaping closes each fragment's end, and one pass repairs the seams.** Readers escape each text node on its own and join the results, so a construct split across elements was never escaped. `escapeInline` closes each piece's end, as its `_` rule already did: a trailing `\` is doubled and a trailing `<`, `!`, or partial entity is escaped (19 of the corpus's 78,296 fragments). Escaping every leading `(` or trailing `]` instead would touch 1,432 or 625. `joinInlineSeams`, run over finished inline Markdown, escapes any `](` not followed by a web or mail destination and any `!` before a link, joins touching formulas, and joins touching code spans, whose fences would meet as one run; code spans, autolinks, and destinations stay as written. Inline TeX cannot end its own `$…$` or open a code span: a `$` is escaped, a trailing backslash becomes a control space, and a backtick is written `\grave{}`, the one spelling both KaTeX's and MathJax's supported-function lists carry. Both `escapeInline` and the seam pass write a bare URL GFM links (`https://…`, `www.…`) that holds or meets an escape, a marker, a link written after it, or a sub- or superscript's closing brace as an explicit link to the URL as the source has it. Outside link text, escaped text never yields a live HTML node. A bare URL can still run into sub- or superscript notation or a citation written right after it (`https://a.co/x^{2}`); source text that spells `](` and a web or mail scheme across two text nodes makes a link the seam pass keeps, since a destination `link` writes holds `*`, `~`, `_`, `^`, braces, and brackets as written, so its destination can run on through emphasis or script notation written after it (`[](http:` then a struck-through `)` links `http:~~`); and renderers that run mdast's text pass for autolink literals also link a `www.` or `https://` after any punctuation, to the next space. Each gives a link destination the source did not hold, as text, never HTML. Emphasis pairs by CommonMark's flanking rules as micromark applies them, and `toText` reads markers as GFM does.
- **Emphasis that a word beside its marker blocks: move the edge punctuation outside the marker.** Where punctuation at the emphasized text's edge meets a word outside the marker (`*daf-16-*dependent`, `a**(x)**b`), the marker can take only one role and GFM prints it literally. The seam pass moves that punctuation across the marker (`*daf-16*-dependent`, `a(**x**)b`), keeping every character in order; an inline formula at the very edge moves whole. Emphasis over punctuation alone, or a pair whose markers still would not pair, loses its markers and keeps its text; where one run holds the markers of two pairs (`**Table 1*.***`), punctuation moves across the whole run and a dropped pair takes only its own markers (`**Table 1.**`). Two spans of one kind that touch (`**K****-step**`) meet as one run GFM reads as neither closer nor opener, so they join into one span (`**K-step**`). Writing the letter beside the marker as a character reference (`*…*&#87;e`) also renders, but it reads badly to a person or a model, the readers this Markdown is for. Only pairs GFM does not form as written are touched: repairs start from the runs it leaves unpaired and follow the pairs those take over. Where GFM pairs every run whole but not as the source nested them, the string cannot say which pairs were meant, so it is left as written.
- **Optional peers for HTML and PDF engines.** A consumer that parses only JATS installs one dependency.
- **Publisher HTML walked directly, not through a readability extractor.** Defuddle, run on a PLOS article, turned the reference list into footnotes holding only "View Article" links, dropped every figure caption, and stripped the class attributes publisher pages mark abstracts, figures, and references with.
- **A well-formedness check before every XML parse.** fast-xml-parser accepts markup that is not well-formed and silently drops what follows the fault (an unescaped `<` in `p < 0.05` loses the rest of the section), and its own validator is deprecated in favor of a package that brings a second XML parser. A single-pass scan in `src/xml/well-formed.ts` turns that silent loss into a `malformed` result, including the two shapes the parser drops whole: a start tag whose name runs into something other than whitespace, `/`, or `>` (`<or= 2/>` reads as an empty element), and a `<!` declaration outside a DOCTYPE (`x<!y>`). It skips a comment or processing instruction in a DOCTYPE's internal subset whole, so a quote in one (`<!-- don't -->`) opens no literal. fast-xml-parser rejects any processing instruction in the subset, so the pre-parse pass removes them; they declare nothing it reads.
- **Unscoped on npm.** The package is meant for any TypeScript project that reads papers; the cyanheads name travels with the repository, the npm maintainer, and the README.
- **Detection reads the payload, not the transport.** A `Content-Type` or URL says what a server meant to send; the bytes say what arrived, and a challenge page served for a PDF URL is the case that matters. Detection sniffs the opening bytes only, and challenge pages are left to the HTML parser, which reports them as `blocked`.
- **PDF structure from typography, without a model.** A PDF records where text is drawn, not what it is. The parser reads text runs with their fonts from pdf.js (through `unpdf`), finds each page's column gutter, and infers structure from size, weight, numbering, and the names sections usually carry. It runs anywhere with no service to call; Grobid remains the better reader, and its TEI is a format of its own.
- **Document-wide PDF reading budgets.** `maxInputBytes` and `maxPages` alone do not bound the work pdf.js does on a document, so `parsePdf` also stops at `maxTextItems`, `maxTextChars`, or `maxOperators`, each counted across the document because none of the three bounds the others, with defaults of the corpus's densest page (for operators, its heaviest paper's per-page average) times 300 pages. A stop, or a page pdf.js cannot load, keeps what was read and warns `truncated-input`; text is streamed so a text budget stops mid-page. One page's own pdf.js work stays unbounded, so a hard time or memory bound needs a worker or process the caller can terminate. A caller's `signal` stops reading at the next page boundary the same way: pdf.js gives control back only between pages, so with a signal each page first waits one `setTimeout(…, 0)` turn, the one Bun, Node, and Workers all have, in which a due timeout aborts it. A turn costs about 10 ms a page on Bun, so none is taken without a signal.
- **Legal formats in a sibling package.** Akoma Ntoso is the legal counterpart of JATS, with its own model (acts, divisions, provisions), so a shared package would only blur both.
- **Element citations laid out as PMC prints them.** A JATS `<element-citation>` holds its fields with no punctuation, in whatever order the publisher lists them, so reading them in source order gave `Nat. Rev. Genet. 21 2020 207–226`. The parser writes `Source. 2020;21:207–226.` whatever the order, matching the `<mixed-citation>` text most PMC deposits carry, so a reference list reads the same whichever form a deposit uses.
- **Europe PMC's Associated Data digest and history note are dropped.** The generated `sec-type="associated-data"` section repeats the article's own supplementary files, data availability statement, and data citations, which the parser already reads where the article places them; the generated `sec-type="history"` note repeats received and accepted dates.
- **A note group titled for its contents is a section.** JATS `<fn-group>` is a footnote container, but eLife and PeerJ put competing interests, author contributions, and data availability in titled groups. Such a group, or a Europe PMC `sec-type="fn-group"` wrapper titled other than `Footnotes`, reads as a section under its title, each note led by the authors whose `<xref ref-type="fn">` points at it; any other group stays footnotes.
- **A footnote is text.** `Footnote` is shared by every format and holds one line of inline Markdown, so block content a source puts in a note is written into its text, in order: a list's items, a formula as inline math (else its text), code as inline code, the blocks of a quote or box, and the label and caption of a figure, table, or supplement. A table's rows do not fit in a line, so a table in a note keeps its label and caption and warns `unhandled-element`. Of the 94 notes in `<fn-group>` or `<author-notes>` across the 38 JATS fixtures, one holds a non-paragraph block.
- **A PDF note is told from front matter by its label and page.** A zone of small lines closing a page column is read by its first line. Opening with a number or note mark (set smaller or on its own line, or a number, a space, and a capital), it is footnotes, one per label, unless on the first page it names an institution, an e-mail address, correspondence, ©, or a licence. Unlabelled on the first page it is front matter and dropped; unlabelled on a later page it stays in its section. Only zones before the reference list count: end matter after the last reference opens back-matter sections at bold labels (`Conflict of Interest:`).
- **One table budget per document, spent where the grid is built.** A spanned cell's text is repeated in every position it covers, and every renderer writes each copy. `buildGrid` charges one budget per document: copies of spanned cells up to 1,000,000 characters, past which a covered position is empty while the cell's own position keeps its text, and grid cells up to 2,000,000, past which a table's remaining rows are dropped. It is spent at parse time because the grid is allocated there, which bounds every renderer at once, and only the parser can warn `truncated-input` for each table it cut. It is per document because a per-table cap multiplies with the number of tables. The PDF parser builds its grids from cell positions rather than spans and charges the same cell budget. The corpus peaks near a thousand copied characters and under a thousand cells.
- **On a titled publisher page with no abstract, prose after the byline opens the body.** The run between the title heading and the first section heading is byline and dates on nearly every page, so it is dropped whenever the page has an abstract: an abstract heading, or an element in the run whose class or ID token is `abstract` (a headingless `<div class="abstract">`, arXiv's `<blockquote class="abstract">`). Without one, the run's blocks from its first prose paragraph onward become an untitled first body section, link lists left out. A paragraph reads as prose with 20 or more words, fewer than half of them capitalized; a sentence's stop at its end, citation markers, brackets, and quotes after it set aside; and no front-matter label (`Copyright`, `©`, `Citation`, `Received`, `Accepted`, `Published`, `Editor`, `Funding`, `Competing interests`, `License`, `Keywords`, `Correspondence`) opening it. All six HTML corpus pages have an abstract heading; their runs hold 121 paragraphs and list items, all byline or furniture, the longest 22 words, and the test accepts none of them while accepting 24 of the 26 opening paragraphs of those pages' body sections (the two it rejects lead into a display equation). The run starts after the title heading, whose container is split around it, so nothing set before the title enters the body.
- **A landing page warns `no-body`, with no code of its own.** A page carrying front matter and an abstract but no article text (an IACR ePrint page, a publisher's abstract page) parses as just that, and its `no-body` message reads `The page has an abstract but no article text: a landing page`. A `landing-page` code would carry the same signal and add a public `ParseWarningCode` member every consumer switching on codes must handle; a body-length threshold in each consumer would be a guess repeated everywhere. Such pages often set the title below `<h1>`, so the title heading is the first outline `<h1>`, else the first outline heading whose text is the `citation_title` (or `dc.title`) tag, whitespace collapsed and case ignored; `Metadata` and `BibTeX` sections are furniture.
- **HTML nesting is bounded before the DOM is built.** `linkedom` builds whatever depth the markup asks for, so recursive walkers overflowed the stack (Node from about 1,000 levels, Bun from 10,000) and walkers reading each element's subtree grew quadratically in depth. `loadBoundedDocument` (`src/html/dom.ts`) scans the markup once and drops the tags of elements that would open deeper than `MAX_XML_DEPTH` (256), the bound the XML parser already applies: each dropped tag becomes a space, a close tag whose open tag was dropped goes too, the text stays, and the parser warns `truncated-input` once. The scan mirrors htmlparser2's stack, which `linkedom` parses with, not the HTML standard's tree builder: an implied close closes only the innermost element (`<p><li><td>` repeated nests), `<x/>` opens an element outside `<svg>` and `<math>`, and raw text is exactly what its tokenizer reads raw. Counting depth any other way would let a page nest past the bound in the tree `linkedom` actually builds. The bound alone leaves a 256-deep chain up to ~96× slower than flat markup, so each walker computes its subtree facts (holds a block, holds an outline heading, prose and text length, its text as a link-list check reads it) once per element. A list keeps text that sits between its items, so a list whose `<li>` tags the bound dropped keeps its text. The deepest HTML fixture nests 39 levels.
- **Lists, quotes, and boxes nest eight levels deep in the Markdown.** Each level re-prefixed every line inside it, so output grew with depth times lines, and the renderer recursed as deep as the document. The list, quote, or box at the eighth level renders everything inside it at its own prefix, walked with a stack instead of recursion: deeper list items keep their markers at its items' indentation, and deeper quotes and boxes add no `>`. Nothing is dropped, and nesting up to eight levels renders as before; the corpus nests lists two deep at most.
- **Character references the XML decoder cannot read become U+FFFD.** fast-xml-parser drops a reference to U+0000 or a surrogate and leaves one past U+10FFFF as text; the HTML and LaTeXML parsers read all three as U+FFFD, as the HTML spec does. One pass before the XML parse rewrites them to `&#xFFFD;`, skipping CDATA sections, comments, and processing instructions, so every format reads them alike. No warning: the replacement character marks the spot.
- **`<?CDATA …?>` is the one processing instruction read as content.** IOP's Crossref deposits put a formula's TeX in a `<?CDATA …?>` instruction inside `<tex-math>`, beside a `<?MML …?>` one, and fast-xml-parser keeps no instruction's content even with `ignorePiTags` off. The same pre-parse pass rewrites each `CDATA` instruction as the CDATA section it stands for, splitting a `]]>` in its content across two sections; a `<?CDATA` inside a CDATA section, a comment, or another instruction stays as written. The pass reads each start tag and declaration whole, as the well-formedness check does, so a `<!--` or `<?` in an attribute value or an entity value cannot shift where it resumes into a CDATA section, where the `]]>` it writes would end that section early and turn its text into markup. Every other instruction, MathML's twin and PMC's `<?equation-image-name?>` among them, stays ignored.
- **The entity-expansion cap counts only entities a DOCTYPE declares.** fast-xml-parser's default counted every predefined, numeric, and HTML named reference against `maxTotalExpansions`, so an article with 100,001 `&amp;` failed as `malformed`. `appliesTo: 'external'` counts only declared entities, the only ones that expand past a character or two, and the length cap on their expansion still holds.
- **The flat section list ends with the floats, the footnotes, and the references.** A pager built on `toSections` serves only what an entry carries, so the figures and tables outside any section, the footnotes, and the references are its last entries, in `toMarkdown`'s order, with `id` and `kind` `floats`, `footnotes`, and `references`. Each holds the Markdown `toMarkdown` writes for it, from one shared function. Those IDs and `abstract-<n>` are reserved: `issueId` never gives one to a section (a source `abstract-1` becomes `abstract-1-2`), and readers number abstract parts `abstract-<n>-<m>`, so each ID renders one entry.
- **A Grobid TEI outline comes from heading numbers alone.** Grobid writes a section, a paragraph heading, and a numbered list item as the same kind of heading. An unnumbered heading is a paragraph heading of the numbered section before it, whether that section is `2`, `2.`, or `3.1`: of 33 unnumbered headings after a top-level numbered section in 58 documents (50 sampled from OpenAlex and the 8 TEI corpus fixtures), 26 are its paragraph headings (`Remark 3.3`, `Limitations` under `7`), 2 stand on their own, and 5 are page furniture. A one-part number that does not advance the top level (`1.` inside `5.5`) opens a run, and the run's longest prefix after which the outline resumes (`5.6`, `6`, or `5.5.1`) is a numbered list whose items are paragraph headings of the section it interrupts. A run the outline never resumes stays as written: nesting a real section by mistake costs more than missing a list, and in the 50 sampled documents the rule nested 16 headings in 4 with no false positive.
- **PMC IDs, PMIDs, and ORCID iDs are normalized in one place, and a value that is not one is dropped.** Each reader cleaned these its own partial way, so a `PMID:` label, a PubMed or PMC link, or a lowercase `pmc` survived as the field's value, a lowercase ORCID check character lost the iD, and `pending` became `PMCpending`. `normalizePmcid`, `normalizePmid`, and `normalizeOrcid` (`src/model/identifiers.ts`) sit beside `normalizeDoi` and serve every JATS, TEI, and HTML identifier field: each drops a label or a PMC, PubMed, or orcid.org link (and the version of a versioned PMC ID, `PMC123456.1`), matches in any case, and returns `PMC` and digits, digits, or the hyphenated iD with an uppercase `X`, else nothing. Each runs only on a value its source already types as that identifier, so it narrows what is kept rather than finding new ones; a search query in a `pubmed`-typed link (Europe PMC writes them) is no longer a PMID. A field takes the first value of its type that normalizes. Every corpus identifier was already canonical.
- **One arXiv ID grammar for references, typed fields, the watermark, and the page URL.** LaTeXML, HTML, and PDF references each read only a labelled new-style ID: none read an old-style ID, LaTeXML and PDF ignored arxiv.org links, and HTML dropped a printed version. `src/model/arxiv.ts` reads an ID after an `arXiv` label, in an arxiv.org `/abs/` or `/pdf/` link, or bare in the old style; it keeps a printed version (a versioned ID names that version, and `Identifiers.arxiv` already kept it), which arXiv numbers from `v1`, and drops an old-style subject class, as arXiv's preferred external form does (`math.GT/0309136` → `math/0309136`). A field the source types as an arXiv ID (JATS `pub-id-type="arxiv"`, TEI `<idno type="arXiv">`, HTML `citation_arxiv_id`) goes through the same grammar in `normalizeArxiv`, which takes an `arXiv` label, an arxiv.org link, or a bracketed subject class after the ID (`arXiv:1906.00591v1[cs.CL]`, as Grobid keeps it) and returns nothing for a value that is not an ID, so every format holds one value for one ID and a field takes the first of its type that normalizes, as the PMC ID, PMID, and ORCID fields do. The watermark gives a date only with an ID that reads, and an archive without subject classes stamps no brackets (`arXiv:hep-th/9901001v2 10 May 1999`). A bare new-style number could be a page or a volume, so it needs the label or link; a bare old-style ID counts only with an archive arXiv used before April 2007 and a `YYMM` of `9107`–`0703`, so `and/1234567` is not one. An entry's printed ID comes before one a link names. A LaTeXML link holding `#` is an in-page anchor resolved against the paper's own URL, and an empty or query-only link resolves to that URL itself, so neither names a reference. In the corpus, 60 LaTeXML references gain an ID and no other field changes; its four typed arXiv fields (one JATS reference, three TEI `<idno>`s) and ten watermarks read as before.
